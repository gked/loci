# Loci Inbox Skill

Отвечайте пользователю по-русски. Поля frontmatter, имена типов, связей и инструментов оставляйте как есть, на английском.

Обрабатывает loci-stage/ в хранилище в две фазы: анализ, затем выполнение.

---

## 🔒 Шаг 0 — Проверьте доступность хранилища

Вызовите `loci__list_vault` без аргументов. Если вызов завершился ошибкой, передайте текст ошибки дословно — в нём сказано,
что не так и что делать, — и остановитесь; при `LOCI_NOT_CONFIGURED` спросите пользователя, где
должно находиться хранилище (никогда не угадывайте путь и не предлагайте путь по умолчанию), и вызовите `loci__set_vault_root`.

---

## Фаза 1 — Сканирование и представление плана

### Шаг 1.1 — Проверьте наличие существующего плана

Вызовите `loci__get_inbox_plan()`.

- Если `status: approved` или `status: in-progress`: переходите к Фазе 2 — предложите продолжить.
- Если `status: done`: сообщите пользователю, что входящие пусты, покажите итоговую сводку.
- Если `status: no-plan` или `status: pending`: продолжайте со сканированием.

### Шаг 1.2 — Сканирование

Вызовите `loci__scan_inbox()`.

### Шаг 1.3 — Представьте результат пользователю

Покажите сводку:

```
Сканирование входящих завершено:
  Файлы (автоматически):   243 электронные книги + PDF → узлы asset (~5 запусков по 50)
  Контент (вручную):        44 заметки/статьи → узлы document/article (~5 запусков по 10)

Оценка: несколько сессий. Загрузка файлов идёт автоматически; элементы контента требуют
вашей проверки в каждой партии.

Утвердить план и начать? [да / изменить бюджет / отмена]
```

### Шаг 1.4 — Утверждение

Вызовите `loci__approve_inbox_plan()`.

---

## Фаза 2 — Выполнение

Предложите два прохода за сессию: проход по файлам и проход по контенту. Пользователь может выбрать любой или оба.

### Партия файлов (автоматически)

Вызовите `loci__execute_inbox_file_batch()`.

Покажите результаты:
```
Партия файлов завершена:
  ✓ 50 книг загружено
  ✗  2 с ошибкой: [список ошибок]
  ≈  1 уже в хранилище: dune.epub — совпадает с "Dune" (a1b2c3d4)
  → осталось 193 (~4 запуска)

Продолжить следующей партией файлов? [да / перейти к контенту / остановиться]
```

Элементы в `duplicates` не были сохранены — в хранилище уже есть узел с таким названием. Их
файлы в области подготовки сохраняются, а план помечает их как `duplicate`, и план остаётся открытым, пока
пользователь не решит. Для каждого спросите: пропустить → `loci__update_inbox_item(path=..., status="skipped")`;
или сохранить вторую копию → `loci__update_inbox_item(path=..., status="pending", allow_duplicate=true)`,
и следующая партия файлов её сохранит. Никогда не возвращайте в очередь, не спросив.

### Партия контента (с помощью Claude)

Вызовите `loci__get_inbox_content_batch()`.

Для каждого возвращённого элемента:
1. Прочитайте содержимое
2. Классифицируйте (тип, теги, summary) по логике навыка loci-save (Шаги 1–2 из loci-save)
3. Вызовите `loci__resolve_mentions` с именами из содержимого и свяжите подтверждённые совпадения
   (Шаг 3 из loci-save) — вопросы по всей партии объедините в один запрос
4. Вызовите `loci__write_vault`, чтобы сохранить узел. Если он возвращает `duplicate: true`, ничего не
   записано: спросите, обновить ли существующий узел или всё равно сохранить (`allow_duplicate=true`)
5. Вызовите `loci__update_inbox_item(path=..., status="done", uid=<uid>)`

После каждой партии покажите сводку:
```
Партия контента завершена:
  ✓ 10 элементов обработано
  → осталось 34 (~4 запуска)

Продолжить следующей партией контента? [да / перейти к файлам / остановиться]
```

## Завершение

Каждая сессия заканчивается здесь, остановился ли пользователь после одной партии или план достиг `done`.

1. Покажите накопленные итоги: обработано, с ошибками (с текстами ошибок), помечено как дубликат (с
   существующим узлом, которому каждый соответствует), осталось и оценка оставшихся запусков.
2. Сообщите обо всём, что вернули инструменты и что пользователю стоит знать, — предупреждения записи, `_notice`
   с Шага 0, — по одной строке на каждое.
3. `tag_warnings` от `loci__write_vault` собираются за всю сессию, а не сообщаются по каждому
   элементу. Перечислите каждое уникальное предупреждение один раз с узлами, к которым оно относится, и предложите исправление —
   заменить тег названной связью или убрать тег, повторяющий тип или подтип, — одной
   строкой. Применяйте его только после «да», через `loci__patch_vault` для каждого узла.
4. Предложите одно подходящее продолжение: следующую партию того же вида, переключение на другой
   проход или — когда план выполнен — запуск `loci__lint_vault` по загруженному.

---

## 🔒 Общие правила

- Никогда не выполняйте без утверждённого плана.
- Всегда показывайте результаты партии, прежде чем предлагать продолжить — никогда не запускайте цепочку автоматически без подтверждения пользователя.
- Если в партии файлов более 20% ошибок, остановитесь и покажите ошибки, прежде чем продолжать.
- Элементы контента: используйте те же правила классификации, что и в Шаге 1 навыка loci-save.
- Если хранилище стало недоступно во время выполнения, немедленно остановитесь и скажите пользователю проверить сервер.
