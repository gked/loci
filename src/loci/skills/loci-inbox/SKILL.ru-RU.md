# Loci Inbox Skill

Отвечайте пользователю по-русски. Поля frontmatter, имена типов, связей и инструментов оставляйте как есть, на английском.

Разбирает содержимое loci-stage/ в два этапа: сначала разбор, затем исполнение.

---

## 🔒 Шаг 0 — Проверьте доступность хранилища

Вызовите `loci__list_vault` без аргументов. Если вернулась ошибка, передайте её текст дословно — в нём сказано, что не так и что делать, — и остановитесь. При `LOCI_NOT_CONFIGURED` спросите, где должно лежать хранилище (не угадывайте путь и не предлагайте вариант по умолчанию) и вызовите `loci__set_vault_root`.

---

## Фаза 1 — Разбор и план

### Шаг 1.1 — Проверьте, нет ли уже плана

Вызовите `loci__get_inbox_plan()`.

- `status: approved` или `status: in-progress` — сразу переходите к Фазе 2 и предложите продолжить.
- `status: done` — скажите, что входящие пусты, и покажите итоговую сводку.
- `status: no-plan` или `status: pending` — начинайте разбор.

### Шаг 1.2 — Разбор

Вызовите `loci__scan_inbox()`.

### Шаг 1.3 — Покажите план

Покажите сводку:

```
Разбор входящих завершён:
  Файлы (без вашего участия):  243 электронные книги и PDF → узлы asset (~5 запусков по 50)
  Текст (с вашей проверкой):    44 заметки и статьи → узлы document/article (~5 запусков по 10)

По времени: несколько сессий. Файлы загружаются сами; тексты в каждой партии
нужно просмотреть.

Утвердить план и начать? [да / изменить бюджет / отмена]
```

### Шаг 1.4 — Утверждение

Вызовите `loci__approve_inbox_plan()`.

---

## Фаза 2 — Исполнение

За сессию можно сделать два прохода: по файлам и по текстам. Пользователь выбирает один, другой или оба.

### Партия файлов (без участия пользователя)

Вызовите `loci__execute_inbox_file_batch()`.

Покажите результат:
```
Партия файлов обработана:
  ✓ 50 книг загружено
  ✗  2 с ошибкой: [список ошибок]
  ≈  1 уже есть в хранилище: dune.epub — совпадает с "Dune" (a1b2c3d4)
  → осталось 193 (~4 запуска)

Продолжить следующей партией файлов? [да / перейти к текстам / остановиться]
```

Элементы из `duplicates` не сохранены: в хранилище уже есть узел с таким названием. Файлы в промежуточной папке остаются, а план помечает элементы как `duplicate` — это держит его открытым, пока пользователь не решит. По каждому спросите: пропустить → `loci__update_inbox_item(path=..., status="skipped")`; сохранить второй экземпляр → `loci__update_inbox_item(path=..., status="pending", allow_duplicate=true)`, и следующая партия файлов его запишет. Без вопроса в очередь не возвращайте.

### Партия текстов (с участием Claude)

Вызовите `loci__get_inbox_content_batch()`.

Для каждого элемента:
1. Прочитайте содержимое.
2. Определите тип, теги и summary по правилам навыка loci-save (Шаги 1–2).
3. Вызовите `loci__resolve_mentions` с именами из текста и свяжите подтверждённые совпадения (Шаг 3 навыка loci-save); вопросы по всей партии соберите в один запрос.
4. Вызовите `loci__write_vault`, чтобы записать узел. Если вернулось `duplicate: true`, ничего не записано: спросите, обновить существующий узел или всё-таки сохранить новый (`allow_duplicate=true`).
5. Вызовите `loci__update_inbox_item(path=..., status="done", uid=<uid>)`.

После каждой партии показывайте сводку:
```
Партия текстов обработана:
  ✓ 10 элементов разобрано
  → осталось 34 (~4 запуска)

Продолжить следующей партией текстов? [да / перейти к файлам / остановиться]
```

## Завершение

Сессия заканчивается здесь — после одной партии или когда план дошёл до `done`.

1. Покажите итоги: сколько обработано, сколько с ошибками (с текстами ошибок), сколько помечено дубликатами (и с каким существующим узлом совпал каждый), сколько осталось и сколько ещё запусков примерно нужно.
2. Скажите обо всём, что вернули инструменты и что пользователю стоит знать, — предупреждения записи, `_notice` с Шага 0, — по одной строке на каждое.
3. `tag_warnings` из `loci__write_vault` собираются за всю сессию, а не сообщаются по каждому элементу. Перечислите каждое предупреждение один раз, с узлами, к которым оно относится, и предложите исправление одной строкой: заменить тег названной связью или убрать тег, повторяющий тип или подтип. Применяйте только после «да», через `loci__patch_vault` по каждому узлу.
4. Предложите одно уместное продолжение: следующую партию того же вида, переход на другой проход или — если план выполнен — запуск `loci__lint_vault` по загруженному.

---

## 🔒 Общие правила

- Без утверждённого плана ничего не выполняйте.
- Всегда показывайте результат партии, прежде чем предлагать продолжить: без подтверждения пользователя цепочку не запускайте.
- Если в партии файлов больше 20% ошибок, остановитесь и покажите их, прежде чем продолжать.
- Для текстов действуют те же правила классификации, что и в Шаге 1 навыка loci-save.
- Если посреди работы хранилище стало недоступно, сразу остановитесь и попросите пользователя проверить сервер.
