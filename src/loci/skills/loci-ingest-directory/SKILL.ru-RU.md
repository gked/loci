# Loci Ingest Directory Skill

Отвечайте пользователю по-русски. Поля frontmatter, имена типов, связей и инструментов оставляйте как есть, на английском.

Создаёт узлы хранилища для файлов из указанного каталога, у которых узлов ещё нет. Использует frontmatter `has_asset` со `scheme: local`.

---

## Шаг 1 — Подтвердите каталог

Если путь не назван, спросите его. Подтвердите:
- точный путь (при необходимости разверните `~` в полный);
- нужен ли рекурсивный обход подкаталогов (по умолчанию нет).

---

## Шаг 2 — Разбор каталога

Вызовите `loci__scan_directory(path=<directory>, recursive=<bool>)`.

Если в результате есть ключ `"error"`, сообщите об ошибке и остановитесь.

Покажите пользователю:
- сколько файлов нашлось всего;
- сколько уже зарегистрировано (для них есть узлы в хранилище) — с именами файлов и UID узлов;
- сколько не зарегистрировано — с именами файлов, определёнными форматами и `suggested_type` (и `suggested_subtype`, где он есть), которые предлагает разбор.

Если зарегистрировано всё, скажите об этом и остановитесь.

Если есть незарегистрированные файлы, попросите подтверждение:
> «Незарегистрированных файлов: N. Создать для всех узлы хранилища?»

Дождитесь ответа, прежде чем идти дальше.

---

## Шаг 3 — Прочитайте онтологию и словарь схем

Вызовите `loci__read_meta(file="ontology")`: это источник истины о схеме — обязательные и необязательные поля и допустимые значения enum для типов, которые вы будете записывать (`document`, `asset`).

Вызовите `loci__read_meta(file="scheme-dictionary")`: он подтверждает допустимые имена схем и обязательные поля. Убедитесь, что у `local` обязателен `path` и что неизвестные схемы вы не используете.

---

## Шаг 4 — Создайте узлы (по одному на незарегистрированный файл)

Для каждого файла из `unregistered`:

### 4a — Соберите метаданные

- **title**: `suggested_title` из результата разбора (читаемое имя файла), если пользователь его не поправил.
- **format**: поле `format` из результата разбора (расширение без точки).
- **type**: `suggested_type` и `suggested_subtype` из разбора — электронные книги это `asset` /
  `book`, всё остальное `document`. Меняйте, только если пользователь говорит, что предложение неверно.
- **summary**: одно предложение о том, что это за файл, — по имени, формату и тому, что лежит рядом в каталоге.
  Содержимое не выдумывайте: пишите только то, что следует из имени файла и формата.
- **tags**: 2–4 тега в нижнем регистре через дефис, выведенные из имени файла и формата.
- **domains**: выведите из контекста каталога и имени файла. Если неясно, не указывайте или поставьте `technology-engineering`.

### 4b — Запишите узел

Вызовите `loci__generate_uid`, чтобы получить UID.

Вызовите `loci__write_vault` с такими полями:
```
type:    <type>
title:   <title>
summary: <summary>
tags:    <tags>
domains: <domains>
body:    "# <title>\n"
extra_fields:
  uid: <uid from generate_uid>
  status: evergreen
  subtype: <subtype>
  has_asset:
    - format: <format>
      primary: true
      locations:
        - scheme: local
          path: <absolute path from scan result>
```

`status` и `subtype` обязательны для обоих типов: без них `write_vault` узел не примет. Для `document` `subtype` — `note`, если файл явно не `report`, `transcript`, `spec`, `plan`, `meeting-notes`, `essay` или `journal`. Для `asset` `subtype` — `book`, и в `extra_fields` добавляется:
```
  storage: digital
```

`write_vault` сам проверяет дубликаты. Если он вернул `duplicate: true`, ничего не записано: покажите заголовок и путь существующего узла и спросите, пропустить файл или всё же создать второй узел (для этого вызовите ещё раз с `allow_duplicate=true`). Дождитесь ответа, прежде чем переходить к следующему файлу.

---

## Завершение

Когда обработаны все файлы:

1. Покажите сводку: создано N узлов (заголовки и UID), пропущено M файлов (имена и причины).
2. Скажите обо всём, что вернули инструменты и что пользователю стоит знать, — предупреждения записи, `_notice` из проверки доступности, — по одной строке на каждое.
3. `tag_warnings` собираются за весь прогон, а не по каждому файлу: каталог электронных книг с тегом `book` даст одно и то же предупреждение N раз. Перечислите каждое предупреждение один раз, с узлами, к которым оно относится, и предложите исправление одной строкой: заменить тег названной связью или убрать тег, повторяющий subtype. Применяйте только после ответа «да», через `loci__patch_vault` по каждому узлу.
4. Предложите одно уместное продолжение: разобрать соседний каталог или прогнать `loci__lint_vault` по новым узлам.

---

## 🔒 Правила

- **Не угадывайте при неясных именах файлов.** Если тип или заголовок действительно непонятны, спросите пользователя.
- **Всегда показывайте результат разбора до первой записи.** Пользователь должен его подтвердить.
- **Один файл — один узел.** Несколько файлов в один узел не объединяйте.
- **Путь сохраняйте ровно таким, каким его вернул разбор** (абсолютным). Не делайте его относительным, если только файл не лежит внутри корня loci.
- **Скрытые файлы не загружайте** (те, чьё имя начинается с `.`): разбор их и так пропускает.
