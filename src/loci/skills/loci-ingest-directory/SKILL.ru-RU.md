# Loci Ingest Directory Skill

Отвечайте пользователю по-русски. Поля frontmatter, имена типов, связей и инструментов оставляйте как есть, на английском.

Создаёт узлы хранилища для файлов указанного каталога, у которых их ещё нет, используя frontmatter `has_asset` со `scheme: local`.

---

## Шаг 1 — Подтвердите каталог

Если путь к каталогу не указан, спросите его у пользователя. Подтвердите:
- Точный путь (при необходимости разверните `~` в полный путь)
- Нужно ли сканировать подкаталоги рекурсивно (по умолчанию: нет)

---

## Шаг 2 — Сканирование

Вызовите `loci__scan_directory(path=<directory>, recursive=<bool>)`.

Если результат содержит ключ `"error"`, сообщите об ошибке и остановитесь.

Покажите пользователю:
- Общее число найденных файлов
- Число уже зарегистрированных (имеющих узлы в хранилище) — перечислите их имена файлов и UID узлов
- Число незарегистрированных — перечислите их имена файлов, определённые форматы и `suggested_type`
  (с `suggested_subtype`, где он задан), который сканирование предлагает для каждого

Если все файлы уже зарегистрированы, сообщите об этом и остановитесь.

Если есть незарегистрированные файлы, попросите пользователя подтвердить, прежде чем продолжать:
> «Найдено N незарегистрированных файлов. Создать узлы хранилища для всех?»

Дождитесь подтверждения, прежде чем продолжать.

---

## Шаг 3 — Прочитайте онтологию и словарь схем

Вызовите `loci__read_meta(file="ontology")` — это источник истины о схеме: обязательные поля, необязательные поля и допустимые значения enum для типов, которые вы будете записывать (`document`, `asset`).

Вызовите `loci__read_meta(file="scheme-dictionary")` — подтверждает допустимые названия схем и обязательные поля.
Убедитесь, что `local` требует `path` и что неизвестные схемы не используются.

---

## Шаг 4 — Создайте узлы (по одному на каждый незарегистрированный файл)

Для каждого файла из `unregistered`:

### 4a — Определите метаданные

- **title**: `suggested_title` из сканирования (читаемое имя файла), если пользователь не исправил его
- **format**: поле `format` из сканирования (расширение файла без точки)
- **type**: `suggested_type` и `suggested_subtype` из сканирования — электронные книги это `asset` /
  `book`, всё остальное `document`. Переопределяйте, только если пользователь говорит, что предложение неверно.
- **summary**: одно предложение о том, что это за файл, на основе его имени, формата и контекста каталога.
  Не выдумывайте содержимое — описывайте только то, что можно вывести из имени файла и формата.
- **tags**: 2–4 тега в нижнем регистре через дефис, выведенные из имени файла и формата.
- **domains**: выведите из контекста каталога и имени файла. Если неясно, опустите или используйте `technology-engineering`.

### 4b — Запишите узел

Вызовите `loci__generate_uid`, чтобы получить UID.

Вызовите `loci__write_vault` с:
```
type:    <type>
title:   <title>
summary: <summary>
tags:    <tags>
domains: <domains>
body:    "# <title>\n"
extra_fields:
  uid: <uid from generate_uid>
  status: evergreen
  subtype: <subtype>
  has_asset:
    - format: <format>
      primary: true
      locations:
        - scheme: local
          path: <absolute path from scan result>
```

`status` и `subtype` обязательны для обоих типов, и `write_vault` отклонит узел без них. Для `document` `subtype` равен `note`, если только файл явно не является одним из `report`,
`transcript`, `spec`, `plan`, `meeting-notes`, `essay` или `journal`. Для узлов типа `asset`
`subtype` равен `book`, и `extra_fields` дополнительно содержит:
```
  storage: digital
```

`write_vault` сам проверяет дубликаты. Если он возвращает `duplicate: true`, ничего не
записано: покажите пользователю заголовок и путь существующего узла и спросите, пропустить ли этот файл
или всё же создать второй узел (вызовите снова с `allow_duplicate=true`). Дождитесь ответа,
прежде чем переходить к следующему файлу.

## Завершение

После обработки всех файлов:

1. Покажите сводку: создано N узлов (заголовки и UID), пропущено M файлов (имена файлов и причины).
2. Сообщите обо всём, что вернули инструменты и что пользователю следует знать, — предупреждения записи, `_notice`
   из проверки доступности, — по одной строке на каждое.
3. `tag_warnings` собираются по всему прогону, а не сообщаются по каждому файлу: каталог электронных книг
   с тегом `book` даёт одно и то же предупреждение N раз. Перечислите каждое различное предупреждение один раз
   с узлами, к которым оно относится, и предложите исправление — заменить тег названной связью или убрать
   тег, повторяющий subtype, — одной строкой. Применяйте его только после ответа «да», через `loci__patch_vault`
   для каждого узла.
4. Предложите одно подходящее продолжение: сканирование соседнего каталога или запуск `loci__lint_vault`
   по новым узлам.

---

## 🔒 Правила

- **Никогда не угадывайте при неоднозначных именах файлов.** Если тип или заголовок действительно неясны, спросите пользователя.
- **Всегда показывайте результат сканирования, прежде чем что-либо записывать.** Пользователь должен подтвердить.
- **Один узел на файл.** Не объединяйте несколько файлов в один узел.
- **Сохраняйте путь как есть из результата сканирования** (абсолютный путь). Не делайте его относительным, если только файл не находится внутри корня loci.
- **Не импортируйте скрытые файлы** (начинающиеся с `.`) — сканер уже исключает их.
