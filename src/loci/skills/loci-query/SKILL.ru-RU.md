# Loci Query Skill

Отвечайте пользователю по-русски. Поля frontmatter, имена типов, связей и инструментов оставляйте как есть, на английском.

Извлекает содержимое хранилища Loci и синтезирует его, используя слой графа.

---

## 🔒 Шаг 0 — Проверьте, что хранилище доступно

Вызовите `loci__list_vault` без аргументов. Если вызов завершился ошибкой, передайте текст ошибки дословно — в нём сказано, что не так и что делать, — и остановитесь; при `LOCI_NOT_CONFIGURED` спросите пользователя, где должно находиться хранилище (никогда не угадывайте путь и не предлагайте путь по умолчанию), и вызовите `loci__set_vault_root`.

Если в результате есть ключ `_notice`, покажите его одной строкой к сведению, прежде чем продолжить.

---

## Режимы запроса

Определите, какой режим подходит под запрос пользователя, и следуйте его процедуре.

---

### Режим 1 — Поиск: «что я знаю о X?»

Применяйте, когда пользователь называет конкретную тему, человека, проект или понятие.

1. Вызовите `loci__search_vault(query=<keyword>)`, чтобы найти подходящие узлы. По умолчанию поиск идёт только по активным узлам; передайте `state="archived"`, чтобы искать в архивном содержимом, или `state=None`, чтобы искать везде.
2. Если результатов несколько: покажите список и спросите, какой нужен (или «все»).
3. Для каждого целевого узла вызовите `loci__read_vault(path=<path>)`, чтобы прочитать полное содержимое.
4. Вызовите `loci__query_neighbors(uid=<uid>)`, чтобы получить прямые связи с их типами и направлениями.
5. Представьте: содержимое узла, затем раздел «Связано с:», где перечислены соседи с типом, типом связи и направлением (входящая/исходящая).

**Если целевой узел имеет тип `topic`:** темы — это хабы графа, поэтому автоматически переходите к Режиму 3 (окрестность), не дожидаясь просьбы: вызовите `loci__query_related(uid=<uid>, depth=2)` и представьте всю окрестность, сгруппированную по расстоянию. Когда пользователь ищет тему, он почти всегда хочет «показать всё, что относится к этому понятию».

Если поиск ничего не нашёл, прямо скажите об этом пользователю — не выдумывайте содержимое.

---

### Режим 2 — Просмотр: «покажи все задачи» / «заметки с тегом python» / «открытые задачи в проекте X»

Применяйте, когда пользователю нужен список, отфильтрованный по одному или нескольким атрибутам.

`loci__find_nodes` поддерживает любую комбинацию:
- `type` — тип узла (task, document, project, article, asset, …)
- `subtype` — точное совпадение внутри типа: task `bug | feature | question | chore`;
  document `meeting-notes | report | spec | plan | transcript | essay | journal | note`;
  article (носитель: `book`, `paper`, …); entity `person | organization | place`;
  asset `book | video | music | …`. Предпочитайте его тегу всякий раз, когда пользователь называет вид объекта — «мои эссе», «открытые баги», «протоколы встреч с X» — это запросы по subtype.
- `tag` — узел должен содержать этот тег
- `status` — точное совпадение (todo, done, active, …)
- `state` — видимость по жизненному циклу; по умолчанию `"active"` (архивные узлы исключаются автоматически). Передайте `state="archived"`, чтобы показать только архивные узлы. Передайте `state=None`, чтобы включить все узлы независимо от состояния.
- `due_before` / `due_after` — строки с датой ISO (YYYY-MM-DD)
- `created_after` / `updated_after` — строки с датой ISO
- `related_to` — UID; возвращать только узлы, связанные с этим узлом любым ребром
- `language` — код языка (en, ru, de, …)

1. Вызовите `loci__find_nodes(...)` с фильтрами, соответствующими запросу пользователя.
2. Представьте результаты кратким списком: `[type] title — summary`.
3. Предложите прочитать любой элемент целиком: «Прочитать какой-нибудь? Просто скажите, какой».

Если запрос неоднозначен (например, нельзя вывести ни тип, ни тег), спросите до вызова.

**Запросы по библиотеке:**
- Все книги, которыми вы владеете: `find_nodes(type="asset", subtype="book")`
- Книги, которые вы прочитали (сохранённое содержимое, а не имеющиеся экземпляры): `find_nodes(type="article", subtype="book")`
- Все журналы чтения: `find_nodes(type="log", tag="reading")`
- Журналы чтения по конкретной книге: `query_neighbors(uid=<book_uid>)` — ищите соседей типа `log` по связи `about`
- Книги в процессе чтения: `find_nodes(type="log", tag="reading")`, затем прочитайте каждый узел и проверьте `log_status` — `find_nodes` не фильтрует по пользовательским полям вроде `log_status`

---

### Режим 3 — Окрестность: «что связано с X?» / «покажи всё вокруг Y»

Применяйте, когда пользователь хочет исследовать связи узла.

1. Найдите узел через `loci__search_vault(query=<keyword>)`.
2. Вызовите `loci__query_related(uid=<uid>, depth=2)`.
3. Результат может быть большим. Отберите, что показывать, по своему суждению:
   - Прочитайте заголовки и типы из результата (пока без полного чтения).
   - Выберите подмножество, наиболее релевантное запросу пользователя, по заголовку, типу и расстоянию.
   - Отдавайте предпочтение узлам с distance=1 и узлам, чьи заголовки тематически близки к запросу.
   - Жёсткий предел: читайте целиком не более 8 узлов в одном ответе.
4. Сгруппируйте выбранные результаты по расстоянию:
   ```
   Direct connections (distance 1):
     [task] Add networkx to pyproject.toml — belongs-to
     [document] Planning: Claude.ai Remote MCP — belongs-to

   2 hops away (distance 2):
     [project] loci
   ```
5. Если результаты были сокращены, скажите об этом: «Показано X из Y связанных узлов. Исследовать какую-то конкретную ветку?»
6. Предложите прочитать любой узел или углубиться в ветку.

---

### Режим 4 — Сводка: «подытожь мои заметки о X»

Применяйте, когда пользователю нужен синтезированный обзор по нескольким связанным узлам.

1. Найдите опорный узел через `loci__search_vault(query=<keyword>)`.
   Если опорного узла нет, используйте `loci__find_nodes(tag=<tag>)` или `loci__find_nodes(type=<type>)`.
2. Вызовите `loci__query_related(uid=<uid>, depth=2)`, чтобы найти окрестность.
3. Из результата выберите узлы, наиболее релевантные запросу пользователя, по заголовку, типу и расстоянию — не читайте все. Жёсткий предел: 8 полных чтений на ответ. Предпочитайте distance=1 и тематически близкие узлы.
4. Синтезируйте: напишите связную сводку, объединяющую содержимое разных узлов. Отметьте, где элементы согласуются, противоречат друг другу или дополняют друг друга.
5. Завершите так: «Источники: [список заголовков с UID]»

Не выдумывайте содержимое, которого нет в файлах хранилища.

---

### Режим 5 — Путь: «как X связан с Y?»

Применяйте, когда пользователь хочет понять цепочку связей между двумя узлами.

1. Найдите оба узла через `loci__search_vault`.
2. Вызовите `loci__query_path(uid_from=<uid1>, uid_to=<uid2>)`.
3. Если путь существует, представьте его цепочкой:
   ```
   [document] Planning doc → belongs-to → [project] loci → parent-of → [task] Add networkx
   ```
4. Если пути нет, автоматически перейдите к поиску общих соседей:
   - Вызовите `loci__query_related(uid=<uid1>, depth=2)` и `loci__query_related(uid=<uid2>, depth=2)`.
   - Пересеките два набора результатов по UID.
   - Если общие узлы есть, покажите их:
     ```
     No direct path found. Both connect to:
       [topic] Graph databases (distance 2 from A, distance 1 from B)
     ```
   - Если пересечение пусто, скажите: «Между A и B не найдено связи в пределах 2 шагов».

---

### Режим 6 — Кросс-тема: «что я знаю о X и Y?»

Применяйте, когда в запросе названы две разные темы и пользователь хочет исследовать их вместе.

Признаки: «X и Y», «и X, и Y», «X против Y», «пересечение X и Y».

1. Выделите обе темы из запроса.
2. Вызовите `loci__search_vault` для каждой темы отдельно. Если по любой из них несколько кандидатов, уточните, прежде чем продолжать.
3. Вызовите `loci__query_related(uid=<uid1>, depth=2)` и `loci__query_related(uid=<uid2>, depth=2)`.
4. Пересеките два набора результатов по UID — это узлы, достижимые из обеих тем в пределах 2 шагов.
5. Представьте в трёх разделах:

   ```
   Connects both (shared neighbors):
     [topic] Rationality — distance 1 from ML, distance 2 from Philosophy
     [note] On priors and belief updating — distance 2 from both

   ML neighborhood (X only):
     [article] Attention Is All You Need
     [note] Transformer intuition

   Philosophy neighborhood (Y only):
     [book] Meditations — Marcus Aurelius
     [topic] Stoicism
   ```

6. Если пересечение пусто, скажите об этом и покажите две окрестности рядом, без общего раздела.
7. Применяйте то же суждение о релевантности и тот же предел в 8 прочитанных узлов, что и в Режиме 3 — выбирайте, что показывать, по кратким описаниям, не читайте всё подряд.

---

### Режим 7 — Недавнее: «о чём я думал в последнее время?»

Применяйте, когда пользователь спрашивает о недавней активности, недавних мыслях или о том, что у него на уме.

Признаки: «в последнее время», «недавно», «что у меня на уме», «над чем я работал», «недавняя активность», «что я делал на этой неделе/в этом месяце».

1. Вызовите `loci__query_recent(days=30)`, чтобы получить недавно обновлённые узлы.
2. Если результат пуст, повторите с `days=90`. Если и тогда пусто, скажите об этом — не выдумывайте активность.
3. Сгруппируйте по типу и представьте как структурированную сводку активности:
   ```
   Recent activity (last 30 days):

   Tasks (5):
     [todo] Build loci-query skill — updated 2026-04-15
     [done] Add networkx to pyproject.toml — updated 2026-03-24

   Documents (2):
     Loci Test Framework Implementation Plan — updated 2026-04-16
   ```
4. После сводки предложите: «Углубиться в что-то из этого или показать связи вокруг конкретного элемента?»

---

### Режим 8 — Инсайт: «какие у меня есть закономерности или неочевидные связи?»

Применяйте, когда пользователь спрашивает о закономерностях, мостах или неочевидных связях по всему хранилищу.

Признаки: «инсайт», «закономерности», «неочевидное», «что служит мостом», «между областями», «какие темы», «что связывает между собой», «чего я не замечаю».

1. Вызовите `loci__query_insights()`, чтобы получить узлы-мосты между областями.
2. Если результат пуст, скажите: «Мостов между областями пока не найдено — возможно, в хранилище недостаточно связей между областями».
3. Для 3–5 верхних результатов вызовите `loci__query_neighbors(uid)`, чтобы увидеть, что каждый из них соединяет.
4. Представьте как список наблюдений:
   ```
   Cross-domain bridges in your vault:

   🔗 [document] Loci Asset Registry Design Spec
      technology-engineering ↔ personal-development
      Connected to 8 nodes across both domains

   🔗 [task] Build loci-query skill
      technology-engineering ↔ personal-development
      Connected to 4 nodes
   ```
5. Синтезируйте: напишите 2–3 предложения, определяющие общую закономерность, — какие темы или сюжеты служат мостами между областями? Это и есть инсайт, а не просто список.
6. Завершите конкретным продолжением: «Похоже, [тема/узел] — это связующая ткань между X и Y. Прочитать его целиком и изучить его связи?»

## Замечание об архитектуре

Фильтры `find_nodes` (status, даты срока, related_to, language) были добавлены на этапе NetworkX как явные параметры. У такого подхода есть естественный потолок — каждое новое измерение фильтра увеличивает сигнатуру инструмента.

Целевой вариант — язык запросов к графу (Cypher через Kuzu). Когда эта миграция состоится, `find_nodes` и его список параметров заменит единый инструмент `query_vault`, принимающий строку запроса. Навык будет строить запросы вместо списков параметров, а набор инструментов снова станет минимальным.

А пока используйте `find_nodes` для перечисления с фильтрами. Не обходите его внутри навыка, читая узлы по одному и фильтруя в памяти.

---

## Завершение

Каждый запрос заканчивается здесь, какой бы режим ни выполнялся.

1. Представьте результат в формате режима — ничего, чего нет в файлах хранилища.
2. Если синтез опирался на узлы с distance=2 или на краткие описания без полного чтения, добавьте единственную строку о низкой уверенности из правил ниже. В остальных случаях не добавляйте никаких меток уверенности.
3. Предложите одно подходящее продолжение: прочитать узел целиком, углубиться на шаг или сохранить синтез обратно как новый документ через навык loci-save. Одно предложение, а не меню.

---

## Общие правила

- **Никогда не выдумывайте содержимое.** Сообщайте только то, что есть в файлах хранилища.
- **UID — стабильные идентификаторы.** Всегда передавайте в инструменты графа uid (не заголовок).
- **Сначала прочитайте, потом подводите итог.** Не делайте сводку только по атрибутам узлов графа — всегда вызывайте `loci__read_vault` для полного содержимого.
- **Сигнализируйте о низкой уверенности, а не о высокой.** Не добавляйте метки уверенности к каждому утверждению. Отмечайте только случаи, когда синтез опирается преимущественно на узлы с distance=2 или только на краткие описания без полного чтения, — добавьте единственную завершающую строку, например: «Примечание: часть выводов сделана по слабо связанным узлам — стоит проверить, прочитав исходные файлы».
