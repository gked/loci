# Установка

**Платформа: пока только macOS.** Linux работает в CI, но не поддерживается, Windows не тестировался. Пути агентов и регистрация в Claude Desktop рассчитаны на macOS.

Loci можно запустить тремя способами. **Из PyPI** — путь для тех, кто хочет пользоваться Loci. **Релизный wheel** — тот же пакет, скачанный с GitHub вместо PyPI. **Из репозитория** нужен для разработки.

---

## Из PyPI

Путь для тех, кто хочет *пользоваться* Loci, а не дорабатывать его. Пакет называется
[`loci-vault`](https://pypi.org/project/loci-vault/), веб-интерфейс уже
скомпилирован внутри него — поэтому не нужны ни репозиторий, ни Node, ни сборка.

**Требуется:** Python 3.13+ и [uv](https://docs.astral.sh/uv/).

### 1. Установите пакет

```bash
uv tool install loci-vault
```

Чтобы закрепить версию: `uv tool install loci-vault==<version>`.

> **Пакет на PyPI называется `loci-vault`, а не `loci`.** Имя `loci` на PyPI
> принадлежит стороннему проекту, поэтому не запускайте `uv tool install loci`
> и `pip install loci`. Команды и имя для импорта по-прежнему `loci`.

В PATH попадут оба консольных скрипта: `loci-mcp` (MCP-сервер по stdio)
и `loci` (HTTP API *и* веб-интерфейс, один процесс на
http://127.0.0.1:8765). Если оболочка всё ещё их не находит, каталог инструментов uv
пока не в PATH: выполните `uv tool update-shell` и откройте новую
оболочку.

### 2. Установите навыки и зарегистрируйте сервер

```bash
loci setup                                     # обе команды ниже, один вопрос
```

`loci setup` выполняет две команды ниже для выбранных агентов (если находит
нескольких, спрашивает один раз; `--target claude|hermes|all` пропускает вопрос),
и её можно безопасно повторять. Чтобы выполнить обе половины самостоятельно:

```bash
loci skills                                    # заглушки навыков → ~/.claude/skills/ или ~/.hermes/skills/
loci register                                  # зарегистрировать MCP-сервер
```

Если установлен один агент, обе команды используют его. Если несколько (Claude Code и
Hermes), они спрашивают, какого выбрать. Вопрос пропускается флагами `--target claude`,
`--target hermes` или `--target all`. Вручную регистрация выглядит так:
`claude mcp add --scope user loci loci-mcp` или `hermes mcp add loci --command loci-mcp`.

**Обновление с версии Loci только для Claude:** раньше `loci skills` безусловно писала в
`~/.claude/skills/`. Теперь она сначала ищет агента и останавливается
с сообщением «No supported agent found», если нет ни `~/.claude`, ни `~/.hermes`,
а `claude` и `hermes` не найдены в PATH. `--target claude` выполнит установку
в любом случае. Кроме того, `loci register` добавляет Loci в конфигурацию Claude Desktop на macOS,
если Claude Desktop установлен, и не трогает уже существующую запись `loci`.

В `~/.claude/skills/` попадает заглушка для каждого навыка — его имя и описание
триггера, над строкой «вызови `read_skill` и следуй результату». Сам навык
отдаёт MCP-сервер: он собирает его из встроенной процедуры и
[ваших дополнений](usage.md#настройка-навыков), которые хранятся в хранилище, так что
установленная копия никогда не устаревает.

### 3. Укажите хранилище

Перезапустите Claude Code и скажите ему, где должно лежать хранилище: «укажи Loci
~/loci/vault» — для этого и нужен инструмент `set_vault_root`. Хранилище
создаётся при первом использовании; пока вы не назовёте путь, ничего не записывается.

Выберите папку хранилища так, чтобы она лежала внутри отдельной папки. Loci создаёт
`assets/` и `loci-stage/` как **соседние** с хранилищем каталоги, в его родительской папке
(см. [структуру хранилища](usage.md#структура-хранилища)). Для `~/loci/vault` все три
окажутся рядом в `~/loci/`; для `~/vault` они появятся прямо в вашей домашней
папке.

Сделайте это до запуска `loci`: если хранилище не настроено, сервер отказывается
запускаться. В выводимой ошибке сначала назван `set_vault_root`, затем `setup.py` —
последний существует только в репозитории, так что в случае wheel путь один — `set_vault_root`.

### Обновление

```bash
uv tool upgrade loci-vault      # имя пакета, а не `loci`
```

При следующем запуске `loci-mcp` вашим агентом он обновит заглушки навыков у каждого
агента, у которого Loci уже установлен. Loci никогда не добавляется агенту, у которого
его нет. Чтобы отключить это, задайте `LOCI_SKIP_SKILL_REFRESH=1`. Запустить
`loci skills` вручную по-прежнему можно.

Заметки к каждому релизу начинаются с того, что обновление требует от вас, потому что
`scripts/release_notes.py` вычисляет это сравнением с предыдущим тегом:

- **`META_VERSION` изменилась** — файлы в `vault/meta/` будут пересозданы при
  следующем запуске. Делать ничего не нужно, но ваше хранилище изменится. Ваши собственные
  файлы `*-user.*`, в том числе дополнения к навыкам, не затрагиваются никогда.
- **Добавлен навык или изменено его описание** — заглушка в
  `~/.claude/skills/` (или `~/.hermes/skills/`) устарела до следующего запуска
  `loci-mcp` или до запуска `loci skills`. Изменение самой
  процедуры ничего не требует: сервер отдаёт её «вживую».

Надёжнее взять за правило всё равно запускать `loci skills`: она сравнивает каждую установленную
заглушку с той, которую записала бы, и ничего не делает, если изменений нет.

О том, как собираются и публикуются релизы, см. [Releasing](../development.md#releasing).

## Другие агенты (DeepSeek Harness и прочие)

`loci register` и `loci skills` настраивают Claude Code, Claude Desktop и Hermes.
Для любого другого агента, включая [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)
(`dsh`), Loci не пишет конфигурационные файлы агента: они у каждого свои, а
некоторые — предварительные версии для разработчиков, которые меняются. Эти шаги **не проверялись**.
Если собственная документация агента расходится с ними, верна документация агента.

**Попросите агента настроить себя сам.** Вставьте это в сессию с агентом:

> Настрой Loci для себя. Loci — это MCP-сервер и четыре навыка.
>
> 1. Зарегистрируй MCP-сервер с именем `loci`, который запускает команду `loci-mcp` по
>    stdio. Способ узнай из актуальной документации этого агента и сначала
>    проверь её: формат мог измениться. Если конфигурационный файл — список,
>    в котором сейчас только `[]`, замени `[]`, а не дописывай ниже.
> 2. Найди папку, из которой этот агент читает навыки (папки
>    `<name>/SKILL.md`). Выполни `loci skills --dir <эта папка>`.
> 3. Если этот агент не поддерживает навыки, добавь в его инструкции:
>    «Перед сохранением в Loci или чтением из него вызови инструмент `read_skill`
>    MCP-сервера `loci` и следуй результату».
> 4. Перезапусти или перезагрузи агента, убедись, что инструменты `loci` видны, и расскажи мне,
>    что ты сделал.

**Вручную, для DeepSeek Harness** (по его документации; на реальной
установке не запускалось). Навыки лежат в `$DSH_HOME/skills` (по умолчанию `~/.dsh/skills`):

```bash
loci skills --dir ~/.dsh/skills
```

Команды `dsh mcp add` нет. Добавьте следующее в `~/.dsh/cordis.patch.yml` (для всех профилей)
или в `~/.dsh/profiles/<profile>/cordis.patch.yml`, заменив `[]`, который
есть в новом файле:

```yaml
- insert:
    - id: mcp-loci
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: loci
        transport: stdio
        command: loci-mcp
```

Затем перезапустите `dsh`. `dsh --profile web --dump-config` покажет, загрузилась ли запись.
Её инструменты появятся как `mcp__loci__<tool>`.

## Из релизного wheel

Тот же пакет, скачанный из [GitHub Release](https://github.com/gked/loci/releases)
вместо PyPI. Используйте его, чтобы закрепить сборку, которой нет на PyPI, или когда PyPI
недоступен. Помимо uv нужен [`gh`](https://cli.github.com/).

Файл называется `loci_vault-<version>-py3-none-any.whl` — меняется только
версия, поэтому скачайте его в пустой каталог и установите по маске:

```bash
rm -rf /tmp/loci-wheel
gh release download --repo gked/loci --pattern '*.whl' --dir /tmp/loci-wheel
uv tool install /tmp/loci-wheel/loci_vault-*.whl
```

Без указания тега `gh release download` берёт самый свежий релиз. Чтобы закрепить
конкретный, назовите тег (`v0.2.0`). Каталог предварительно очищается, потому что маска должна
совпасть ровно с одним файлом. Дальше продолжайте с [шага 2](#2-установите-навыки-и-зарегистрируйте-сервер).

Чтобы обновиться, повторите команды с `uv tool install --force`, затем запустите
`loci skills`.

## Из репозитория

Запускает MCP-сервер прямо из клона репозитория. Выбирайте этот путь, если
вы будете менять Loci, а не только пользоваться им; веб-интерфейс здесь
отдельно обслуживает vite, а `setup.py` заменяет `loci skills` + `claude mcp add` из wheel.

**Требуется:** Python 3.13+, [uv](https://docs.astral.sh/uv/), [rclone](https://rclone.org/) (необязательно, для резервного копирования), Node 20+ (необязательно, для веб-интерфейса)

> **Просто хотите пользоваться Loci?** [Установите из PyPI](#из-pypi)
> — без репозитория и Node, а интерфейс уже скомпилирован внутри пакета. Шаги
> ниже предназначены для разработки самого Loci (`make dev`, `make run`).

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/gked/loci.git
cd loci
```

### 2. Инициализируйте

```bash
uv run setup.py
```

Скрипт:
- установит зависимости через uv;
- спросит, где должно лежать хранилище, — абсолютный путь, обязателен, значения по умолчанию нет
  (держите его вне репозитория; `~` раскрывается автоматически);
- спросит, какой удалённый ресурс rclone использовать, если он вам нужен;
- создаст структуру папок хранилища и заполнит словари meta;
- зарегистрирует MCP-сервер в Claude Code и Claude Desktop.

Ответы записываются в `~/.config/loci/config.yml` (или
`$XDG_CONFIG_HOME/loci/config.yml`) — вне репозитория, чтобы установка
без него сохраняла свои настройки. Если в корне проекта лежит старый `config.yml`,
при первом запуске он копируется и переименовывается в `config.yml.migrated`.
Чтобы использовать другой файл, задайте `LOCI_CONFIG`.

### 3. Настройте удалённый ресурс (необязательно)

```bash
cp sync/rclone.conf.sample ~/.config/rclone/rclone.conf
# отредактируйте, указав свои учётные данные
```

Загрузите хранилище с удалённого ресурса при первой настройке:

```bash
./sync/sync.sh pull
```

Прочитайте раздел [синхронизация и резервное копирование](#синхронизация-и-резервное-копирование), прежде чем на это полагаться. Это ручной
скрипт, а не фоновая синхронизация.

### 4. Установите навыки Loci в Claude Code

`uv run setup.py` уже сделал это — шаг 2 устанавливает заглушку для каждого из
четырёх навыков. Чтобы переустановить их или посмотреть, какие устарели:

```bash
uv run loci skills
```

Команда сравнивает заглушку каждого встроенного навыка с тем, что лежит в `~/.claude/skills/`,
сообщает, какие нужно установить или обновить, и спрашивает подтверждение перед записью:

```
Loci skills → /Users/you/.claude/skills

  loci-inbox             install
  loci-ingest-directory  install
  loci-query             up to date
  loci-save              update

2 to install, 1 to update
Proceed? [y/N]
```

Заглушка — это имя навыка и описание триггера над одной инструкцией: вызвать
`loci__read_skill` и следовать тому, что он вернёт. Процедуру отдаёт
MCP-сервер, добавляя в конец [ваши дополнения](usage.md#настройка-навыков),
поэтому правка `src/loci/skills/<name>/SKILL.md` действует сразу, без переустановки.
Заглушка меняется, только когда навык добавлен, удалён или переформулировано его
описание — и git-хуки запускают эту команду за вас, когда pull
приносит такие изменения. `--yes` пропускает подтверждение, `--dir` устанавливает в каталог, отличный
от `~/.claude/skills`.

### 5. Перезапустите MCP-сервер

В Claude Desktop сервером управляет приложение, поэтому просто закройте его и откройте снова. В Claude Code перезапустите сессию или переключите MCP-соединение. Чтобы запустить сервер вручную:

```bash
./run_server.sh
# или напрямую:
uv run loci-mcp
```

### 6. Проверьте

Откройте Claude Code и скажите:

```
Сохрани в моё хранилище loci как заметку: Loci установлен и работает.
```

### Сборка wheel из репозитория

Чтобы установить собственную сборку как полноценный инструмент, с встроенным интерфейсом:

```bash
make wheel                              # dist/*.whl; сначала компилирует app/
uv tool install --force dist/loci_vault-*.whl
```

Используйте `make wheel`, а не голый `uv build`: голая сборка выпускает wheel без интерфейса.
Нужен Node 20+.

## Синхронизация и резервное копирование

**Автоматической синхронизации нет.** Есть тонкая обёртка над rclone, которую вы запускаете
сами. Считайте
работу на нескольких устройствах незавершённой.

`sync/sync.sh` принимает направление и вызывает rclone:

```bash
./sync/sync.sh push     # локальное хранилище  ->  удалённый ресурс  (rclone sync)
./sync/sync.sh pull     # удалённый ресурс     ->  локальное         (rclone sync)
./sync/sync.sh bisync   # в обе стороны        (rclone bisync)
```

Что нужно знать, прежде чем ей доверять:

- **`push` и `pull` — это зеркала, а не слияния.** Обе команды вызывают `rclone sync`, который
  приводит приёмник в соответствие с источником. `pull` перезаписывает локальные изменения, о которых
  удалённый ресурс не знает; `push` делает обратное. Обработки конфликтов нет.
- **`bisync` требует инициализации.** Первый запуск нужно выполнить вручную:
  `rclone bisync <local> <remote> --resync`; это наименее проверенный путь.
- **Локально ничего не запускается по расписанию.** Нет ни наблюдателя, ни демона, ни хука. Если вы
  не запустите скрипт, ничего не сдвинется.
- **Сама синхронизация тестами не покрыта.** Набор тестов проверяет, что `sync.sh`
  находит ваш конфиг (`LOCI_CONFIG`, затем `$XDG_CONFIG_HOME/loci/config.yml` или
  `~/.config/loci/config.yml`, затем `config.yml` в корне проекта), но rclone
  он не запускает.

Если хранилище нужно на нескольких машинах уже сегодня, надёжнее поместить его
в папку, которой уже управляет ваш клиент синхронизации
(Nextcloud, Dropbox, iCloud Drive), и не трогать `sync.sh`.

## Язык

Необязательный ключ `language` в `config.yml` (или переменная окружения
`LOCI_LANGUAGE`) принимает значения `en` (по умолчанию) или `ru-RU`, например
`language: ru-RU`. Он заставляет MCP-сервер отдавать агенту русские процедуры навыков
(`read_skill`) и задаёт язык веб-интерфейса по умолчанию. В заголовке интерфейса
также есть переключатель языка, и браузер запоминает ваш выбор.

## Переменные окружения сервера

Читаются в `src/loci/mcp_server.py`:

| Переменная | Значение |
|---|---|
| `LOCI_TRANSPORT` | `stdio` (по умолчанию) или `sse` |
| `LOCI_VAULT_ROOT` | Путь к хранилищу знаний; переопределяет конфигурационный файл |
| `LOCI_CONFIG` | Путь к конфигурационному файлу; переопределяет `~/.config/loci/config.yml` |
| `LOCI_LANGUAGE` | `en` (по умолчанию) или `ru-RU`; переопределяет `language` в конфигурационном файле |
| `LOCI_PORT` | Только для SSE, по умолчанию `8000` |
| `LOCI_TOKEN` | Только для SSE, необязательная bearer-аутентификация |

> **Предупреждение:** SSE слушает на всех интерфейсах по обычному HTTP. Задайте `LOCI_TOKEN`
> и поставьте перед сервером прокси с TLS, прежде чем открывать его за пределы
> вашей машины. Без токена любой, кто достучится до порта, может читать и
> изменять хранилище.
