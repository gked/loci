# Примеры

Один запрос на каждую ситуацию, что Loci записывает и как вы получаете это
обратно. Каждый пример предполагает, что вы один раз сказали Claude считать
«сохрани», «запомни» и «что я знаю» операциями с хранилищем — см.
[Научите агента один раз](usage.md#научите-агента-один-раз). Пока этого нет,
говорите в запросе «loci» или «моё хранилище».

Каждое сохранение заканчивается одинаково: Claude предлагает тип, подсказывает
связи с уже имеющимися узлами и просит подтвердить перед записью. Скажите
«просто сохрани», если хотите меньше вопросов.

---

## Сохранение

### Закладка — URL, ничего не извлекается

```
Сделай закладку: https://example.com/tools/some-cli
```

→ узел `bookmark` с `source_url` и `site_name`. Содержимое не загружается.

### Статья — то, у чего есть источник, читаемое сейчас или позже

```
Сохрани эту статью: https://example.com/essay-on-attention
Сохрани эту статью и отметь, что она спорит со статьёй на ту же тему, которую я сохранял на прошлой неделе
```

→ узел `article` с `source_url`, `author`, `published_at`, сводкой и
`subtype` (`blog-post`, `paper`, …). Вторая форма добавляет ребро
`contradicts` к более раннему узлу.

### Документ — ваш собственный текст, без цитируемого источника

```
Сохрани это как документ: <вставьте текст или «файл, который у меня открыт»>
Сохрани мои заметки с сегодняшнего дизайн-ревью как протокол встречи
```

→ узел `document` с `status` и `subtype` (`meeting-notes`, `essay`,
`spec`, …). Если текст читается как последовательность шагов, Claude предложит
вместо этого `procedure`.

### Ссылка на файл, который вы храните в другом месте

```
Добавь в хранилище ссылку, не копируя файл: ~/Documents/contracts/lease-2026.pdf
Сохрани ссылку на план на третий квартал в Google Drive: <ссылка>
```

→ узел того типа, которым является содержимое (`document`, `article`, `asset`),
с записью `has_asset`, фиксирующей, *где* лежит файл: `scheme: local` с путём,
`scheme: google-drive` с id файла и так далее. Файл остаётся на месте. Чтобы
копией владел Loci, положите файл в `loci-stage/` и запустите обработку
входящих (ниже).

### Книга, которой вы владеете — на полке или в виде электронной книги

```
Добавь книгу в мою библиотеку: «Думай медленно… решай быстро», Канеман, бумажная, стоит на полке
Добавь электронную книгу в мою библиотеку: ~/Books/name-of-the-rose.epub
```

→ узел `asset` с `subtype: book` и `storage: physical | digital | both`;
для электронной книги добавляется ещё и расположение `has_asset`. Книга,
которую вы *читали*, но не владеете ею, — это `article` с `subtype: book`;
Claude спросит, если не сможет определить сам.

### Заметки о чтении книги

```
Запиши чтение: сегодня начал «Имя розы»
Запиши чтение: дочитал «Имя розы», 5/5. Выделенное: <вставьте текст>
```

→ один узел `log` на каждое прочтение с тегом `reading`, `subject_uid`,
указывающим на книгу, `log_status`, `started_at` / `finished_at`, `rating` и
`highlights`. Перечитывание книги позже создаёт второй `log`, так что два
прочтения — и то, как изменилось ваше мнение, — остаются раздельными.

### Задача

```
Добавь задачу: продлить аренду до 30 сентября, высокий приоритет
```

→ узел `task` с `status`, `due_date`, `priority`, связанный с документом об
аренде, если он есть.

### Проект

```
Начни проект: перестроить садовый сарай. Цели: защита от непогоды к октябрю, не дороже $2 тыс.
```

→ узел `project` с `status`, `goals`, `milestones`, `due_date`. Позднейшие
задачи и заметки получают ребро `belongs-to` к нему, когда вы упоминаете сарай.

### Событие

```
Сохрани событие: стоматолог, 14 октября 10:00, клиника доктора Окафор
```

→ узел `event` с `start_at`, `end_at`, `location`, `participants`.

### Человек, организация или место

```
Сохрани сущность: Дана Окафор, стоматолог в клинике Riverside
Сохрани сущность: клиника Riverside, стоматологическая практика на Main Street
```

→ узлы `entity` с `subtype: person | organization | place` и соответствующими
полями (`roles`, `organization`, `website`, …). На сущности указывают рёбра
`mentions`, поэтому сохранение людей и организаций, с которыми вы имеете дело,
и делает так, что на вопрос «что я знаю о X» приходит ответ с путями.

### Процедура — шаги с результатом

```
Сохрани этот рецепт: <вставьте текст>
Сохрани, как я настраиваю новую машину, как плейбук: <шаги>
```

→ узел `procedure` с `steps`, `expected_outcome`, `inputs`,
`duration_minutes` и тегом формата (`#recipe`, `#playbook`, `#protocol`, …).

### Разговор

```
Сохрани этот разговор в моё хранилище
Сохрани переписку с подрядчиком из почты как разговор
```

→ узел `conversation` с `participants`, `platform`, `model` (для чата с LLM),
`turns`. Для почты `has_asset` указывает на переписку через схему `gmail`, а не
копирует её.

### Тема — хаб без собственного содержимого

```
Создай тему: стоицизм. Привяжи к ней заметки о Марке Аврелии и два журнала чтения
```

→ узел `topic` с `status`; названные узлы получают к нему рёбра. Если вы
используете предмет только как фильтр, лучше подойдёт тег — Claude скажет об
этом.

### Накопившиеся файлы

```
Обработай мои входящие
```

→ сканирует `loci-stage/`, показывает план с количеством и оценками, а после
одобрения загружает возобновляемыми пакетами. Чтобы зарегистрировать папку на
месте, ничего не перемещая: `Загрузи ~/Documents/papers в моё хранилище`.

## Получение

```
Что я знаю о стоицизме?
Что связано с проектом сарая?
Что я сохранил за последние две недели?
Как документ об аренде связан с Даной Окафор?
Покажи все открытые задачи
Покажи журналы чтения, которые я закончил в этом году
Что я думал о «Имени розы», когда читал её в первый раз?
```

Ответы берутся из графа — типов, тегов, статусов, дат и рёбер, — а не из
текстового поиска, поэтому «открытые задачи» — это фильтр по статусу, а
последний запрос идёт от книги к её самому раннему `log`. Обычный поиск тоже
есть: `Найди в моём хранилище «внимание»`.

## Обновление

```
Отметь задачу об аренде выполненной
Добавь заметку в проект сарая: подрядчик назвал цену $1 800
Архивируй документ с планом на третий квартал
Вообще-то эссе о внимании заменяет (supersedes) прошлонедельное, а не противоречит ему — исправь связь
```

→ патчи к существующему узлу. Правки допустимы свободно (вас не блокируют
правила для полей, которых вы не трогаете); архивирование выставляет
`state: archived` и скрывает узел из запросов по умолчанию, не удаляя его.

## Расширение онтологии

```
Определи тип `recipe`, расширяющий `procedure`, с необязательными полями `servings` и `cuisine`
Определи связь `cooked-from`, обратную к `is-based-on`, для записи, фиксирующей приготовление по рецепту
Сохрани этот рецепт как recipe: <вставьте текст>. Порций 4, итальянская кухня
Запиши готовку: сегодня приготовил карбонару, 4/5, cooked-from этот рецепт
Что я готовил по этому рецепту?
```

Первые два запроса дописывают `ontology-user.yaml` и
`relation-dictionary-user.yaml` и вступают в силу сразу; остальные используют
их как любой поставляемый тип. Правила и то, как пользовательский слой
соотносится с каноническим, описаны в
[usage.md](usage.md#расширение-онтологии).
